# 工作流收集策略 —— 从「按分类」到「全平台扫描」

> 状态：2026-11-13 实施并验证
> 涉及工具：`download/collect_platform_sweep.py`、`download/collect_extra_2026-11-13.py`、
> `download/verify_sweep_2026-11-13.py`
> 前置约定见 `AGENTS.md` 3.3（RunningHub 下载一律走登录态）

---

## 一、为什么要改：按分类收集的盲区

原策略是 `collect_by_tag.py <大类/小类> <target>`：按平台分类树里的
**子分类**逐个翻页，跳过本地已见 ID。

这个策略长期跑下来会出现两个问题：

### 1. 已收集的分类会「收尽」，后面全是空转

各分类的 `state.json` 里记着「已见 ID 数」。2026-11-13 盘点时：

| 分类 | 本地已见 | 平台该分类总量 |
|---|---|---|
| 图片生成/图生图 | 35,205 | 33,370 |
| 图片生成/文生图 | 15,374 | 15,334 |
| 视频生成/图生视频 | 28,051 | 27,988 |
| 数字人/数字人 | 7,244 | 7,238 |
| 音频生成/音频生成 | 3,875 | 3,873 |

**本地已见数 ≥ 平台总量**（多出的是同一工作流挂在多个子分类下的重复）。
所以第 2、3 轮翻满 `MAX_PAGES=900` 页也捞不到任何新东西，纯空转。
实测：图生图第 1 轮收 600 个，第 2 轮翻 583 页只多收 258 个且全在前面。

### 2. 真正的新工作流藏在「没收集过的子分类」里

平台分类树有 **42 个子分类**（视频特效 / 二次元 / 海报 / 图片处理 / 摄影 /
影视游戏 / 3D模型 / 创意玩法 / 平面设计 / 电商产品 / 室内外设计 / 风格画作 /
API / AI漫剧 / 视频处理 / 插件 / 其他 …），
而本地只按 7 个主线分类收过。

归类在那些子分类下的工作流，**从来没进过本地任何一份清单**。

实测（2026-11-13）：直接打平台全量列表，扫前 1,800 条 →
本地完全没见过的 ID **1,022 个，占 57%**。

## 二、新策略：全平台扫描

### 接口

```
POST https://www.runninghub.cn/api/portal/template/list
body: {"size":30, "current":N, "sort":"NEWEST"}
```

**不带 `tags` 参数 = 全平台列表**（total ≈ 91,872），无需登录、只读。

带 `tags` 时平台按分类过滤；不带时返回全站 —— 这正是原策略漏掉的那部分。

### 已知 ID 集合（三来源并集）

判断「本地见过没有」不能只看分类清单，要并三份：

1. 各分类 `state.json` 的 `known_ids`
2. 各分类 `ids.txt`
3. **下载目录里已落地的文件名**（`(\d{12,})\.json$` 的 ID 后缀）

第 ③ 项容易漏：有些工作流下载过（甚至已入库学习过），
但从没进过任何一份分类清单 —— 只看 ①② 会把它们当成"新的"重复下载。

### 输出位置

| 产物 | 路径 |
|---|---|
| ID 清单 | `download/ids-by-tag/平台全量/平台全量_ids.txt` |
| meta 表 | `download/ids-by-tag/平台全量/平台全量_meta.csv` |
| 下载目录 | `download/workflows-by-tag/平台全量/` |

独立目录，**不与分类目录混 manifest 账**。
入库时 `import_workflows.py` 会用 `source.rglob("*")` 递归扫描、
按相对路径原样入库，`平台全量/` 自动建成对应的库内目录，无需改配置。

### 产出密度（NEWEST 顺序，2026-11-13 实测）

| 页段 | 新发现 |
|---|---|
| 0–99 | 1,231 |
| 100–199 | 271 |
| 200–299 | 376 |
| 300–399 | 约 36 |
| 400+ | 约 3 / 页 |

曲线合理收敛，尾部趋近于 0。

## 三、两条路线的关系

| 路线 | 工具 | 作用 |
|---|---|---|
| 分类收集 | `collect_by_tag.py` | 补齐某个**已知**分类的深度（某个小类历史条目很多时） |
| 全平台扫描 | `collect_platform_sweep.py` | 兜底发现**跨分类**的新工作流 |

**全平台扫描是主力**：它覆盖 7 个主线分类之外的 35 个子分类。
分类收集只在需要补特定小类深度时再用。

补收从未建过清单的子分类（视频生视频 / 其它视频处理 / 动作迁移）用
`collect_extra_2026-11-13.py` —— 它们是全平台扫描的子集，
但单独收能让 ID 落到对应分类目录，账目更清晰。

## 四、清点口径（易错，必读）

库内 `workflows.id` 存的是**相对路径**，不是纯 ID：

```
视频生成/图生视频/wan2.2_SmoothMix首尾帧生视频_2031673957350379522.json
```

所以：

- ❌ 按路径比对 → 会算出「24,211 未入库」的**错误**数字
  （同一工作流在多个标签目录各存一份，图生视频最典型：
  按路径 8,882 在库，按 ID 26,497 在库，差 17,615）
- ✅ 按 **ID 全局去重** → 才是真口径

真欠账 = 下载目录按 ID 去重后的总数 − 库内 ID 数。
2026-11-13 盘点时：去重后 81,708 个工作流、库内 79,744 → **欠账 2,609**。

用 `download/verify_sweep_2026-11-13.py` 一键出这张表。

## 五、完整收尾链

```
① collect_platform_sweep.py --download      扫全平台 + 下载新增
② collect_extra_2026-11-13.py              补三个从未建清单的子分类
③ verify_sweep_2026-11-13.py               清点真实欠账
④ download/digest_runner.py                消化（入库+建卡+学习）→ 重归纳 → 图谱重建
```

第 ④ 步的编排器自带门禁：每阶段前等外来 `learn_pipeline` / 归纳 / 图谱进程退出
（两条同写 sqlite 会互相覆盖，AGENTS.md 2026-10-19 禁令），
且下载未完成时拒绝启动入库（下载是 `write_bytes` 非原子落盘）。

**注意**：`digest_runner.py` 的 `--plan` 参数只用于下载阶段的清单核对；
消化阶段是 `--skip-collect --skip-download` 全库扫，
所以新增文件只要落在 `download/workflows-by-tag/` 下就会被吃到。
